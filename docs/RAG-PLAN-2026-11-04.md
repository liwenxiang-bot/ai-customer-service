> **进展（2026-11-05 发版 ca83180）**：三期全部上线。PR #57 文档/网址导入与结构感知切块，#58 一期，#61 二期，#62 三期。
> 线上已完成：docs.9e.lv 文档站 113 条知识导入；历史回答 answer_kind 回填（近 30 天有效命中率见后台概览）；
> 125 条知识的 AI 问法生成已排队执行。仍需人工：按第 2.4 节补知识（模板 `docs/knowledge-gap-template-2026-11-04.csv`，未入库）、
> 在「测试检索」里标注 20 条以上评测用例后运行一次校准、在「待审核」里处理人工回复沉淀出的候选。

## 一、结论

1. **检索算法不是瓶颈。** 用 25 个线上真实问法回放线上检索：15 个知识库里有答案的问题全部命中正确条目并排第一；10 个知识库里没有答案的问题，7 个被正确拒绝，3 个误命中是「沾边」条目（订单号→QQ群、兑换码→API中转站、归档→导出记录），分数都只是刚过门槛。
2. **真正的损失在检索之外**，按影响从大到小：
   - 知识覆盖不足：有流量的租户只有 12 条知识，多数不足 100 字；客户问得最多的模型下架、镜像故障、卡密兑换、API Key 用量、套餐区别、代充等主题一条都没有。
   - 回答策略：模型查到沾边资料后仍说「没查到」，却照样带上 [来源N]；近 30 天 217 条「有引用」回答里 62 条是这种，12 条是空回复兜底。
   - 统计口径：后台「知识库命中」= 有引用的回答 ÷ 全部回答，寒暄、转人工、拒答都在分母，上面两类假命中都在分子。
   - 有 29% 的回答（90 天 171/596）根本没有检索，其中约三成是「现在用不了 gpt」这类真实问题。
3. **参数页需要重构，但方向不是「教你调」，而是「不用你调」。** 现在 12 个裸参数里只有 2 个对命中有实际影响，而且靠人眼没法定；应收成一个「严格↔宽松」档位加「一键校准」，其余折叠进高级。
4. 不建议做的事：换 embedding 或 rerank 模型、调分块大小、调融合权重、单纯调高重排分下限。数据表明这些都不是问题所在，调了只会把现在能命中的拉下来。

补齐知识后，真实有效命中率（见第四节口径）预计能从现在的约 50% 提到 70% 以上；上限取决于知识补多少，不取决于代码。

## 二、复检方法与数据

### 2.1 线上数据（近 30 天，排除测试账号与人工消息）

| 指标 | 数值 | 说明 |
|---|---|---|
| AI 回答 | 287 | |
| 有引用的回答（后台口径的「命中」） | 217（75.6%） | 虚高 |
| 其中空回复兜底 | 12 | 「抱歉，我这边没能正常生成回复」，未标降级 |
| 其中回答明说没查到 | 62 | 带引用但内容是「知识库没有相关资料」 |
| 扣除后真正用上资料的回答 | 143（49.8%） | 近似的真实有效命中 |
| 没有调用检索的回答 | 67 | 31 条是要人工，10 条是寒暄，26 条是真实问题 |
| 检索调用命中率 | 89.4%（752 次中 80 次未命中） | 命中 ≠ 答对 |

引用分数分布（90 天，409 条有引用回答的最高重排分）：0.15–0.20 占 324 条（79%），0.20–0.30 占 43 条，0.30 以上只有 39 条。也就是说绝大多数「命中」都贴着 0.15 的门槛，分数分不开对错。

### 2.2 线上检索回放（我自己选的 25 个真实问法，只读，不改数据）

| 类型 | 数量 | 结果 |
|---|---|---|
| 知识库有答案 | 15 | 15 个排第一的都是正确条目 |
| 知识库无答案 | 10 | 7 个正确返回空，3 个误命中沾边条目 |

关键观察：

- 对题的重排分跨度极大：精确问题 0.86–0.93（上传文件报错、验证码、Codex 报错），模糊问题只有 0.17–0.30（「claude code 怎么接入」0.167、「我这边显示限额了」0.209、「如何使用？」0.299）。误命中的沾边条目是 0.159–0.188。**门槛调到 0.2 会丢掉对题的模糊问题，调到 0.3 会丢一半。** 这就是「调参数没用」的直接证据。
- 向量相似度上，对题条目比第二名普遍高 0.1–0.3，区分度明显好于重排分；但无答案时最高相似度也能到 0.55–0.60（订单号→QQ群 0.553），所以向量下限同样切不干净。
- 关键词路径常把「Codex 切换分组报错」「注册时收不到验证码」这两条长条目当候选（分词后词多，容易沾上），重排能压下去，但重排只在候选多于 1 个时才跑，单候选时分数口径直接变成融合分（0.0167），和重排分混在同一张表里。

### 2.3 线上知识库现状

- 12 条已发布知识，3 条（QQ群、API中转站、web镜像）承担了约 70% 的引用，其中 2 条内容只是一个网址。
- 「使用文档」条目正文是一句话加 docs.9e.lv 链接，所以所有「怎么用、怎么配置」的问题都只能答一个链接。
- 另一租户 25 条电商示例知识近 30 天没有任何 AI 回答，不影响统计。
- 对话沉淀（👍 触发）上线以来只产生 3 条候选，因为客户几乎不点赞（90 天有引用的回答被点赞 0 次）。
- 人工坐席近 90 天回复 145 条，平均 12 个字，像「claude 目前停售」「6.1 只有 codex 支持」「官网故障修复中」。太短不能直接当知识，但每一条都准确指出了知识库缺什么。

### 2.4 客户问但知识库没有的主题（90 天未命中与未检索问题归并）

1. 模型可用性：GPT-6.1 没了、Claude 停售、Pro 模型不见了、Grok 找不到账号、Gemini 用不了
2. 镜像故障：打不开、未登录、Content failed to load、车辆异常、卡顿、换号也没用
3. 卡密与兑换：卡密在哪、没保存怎么办、兑换入口、兑换码怎么用
4. API 使用：怎么看 Key、看用量、看调用的模型、数据中心在哪、分组怎么选、Claude Code 怎么配
5. 套餐与订阅：Team/Plus/Pro 区别、订阅能用哪些模型、季卡权益
6. 代充与官方关系：是否代充官方 Plus、镜像是否与官方账号同步、是否官方站
7. 功能支持：画图、上传 Word、Projects 项目入口、归档对话在哪、电脑自动化
8. 交易：订单号在哪找、量大优惠、支付方式、买错了怎么办

## 三、方案总览

分三期，每期独立可上线、可回滚，按「先止血、再补结构、最后自动化」排序。

| 期 | 目标 | 内容 | 工作量 |
|---|---|---|---|
| 一期 | 口径真实、回答诚实、每轮必检 | 回答分类落库、看板改口径、未命中问题列表、引用清洗、首轮强制检索、双查询、两个小 bug | 1–2 天 |
| 二期 | 知识库从「文档」变成「FAQ」 | 同义问法、问法向量、缺口闭环（人工回复→草稿→审核）、文档站导入 | 3–5 天 |
| 三期 | 参数不用人调 | 档位化参数页、后台标注评测集、一键校准、默认值修正 | 2–3 天 |

与代码无关、现在就能做的：按 2.4 的 8 个主题补知识，由你提供答案（我不能替你编业务内容）。这一项对命中率的提升大于所有代码改动之和。

## 四、一期：止血与口径

### 4.1 回答分类落库（新增 `messages.answer_kind`）

每条 AI 回答在落库时打一个标签，之后所有统计都基于它：

| answer_kind | 判定 |
|---|---|
| grounded | 回答正文引用了 [来源N]，且不含「没查到/暂无相关/无法确认」类表述 |
| no_info | 调用了检索，但最终回答说没有资料 |
| general | 没调用检索或检索为空，用通用常识回答 |
| handoff | 本轮转了人工 |
| off_topic | 防滥用拦截的固定拒答 |
| chitchat | 用户消息是寒暄或极短（≤4 字且无业务词） |
| degraded | 模型出错、截断、空回复兜底 |

空回复兜底（「没能正常生成回复」）目前没有标 degraded，一并修正。存量数据写一次回填脚本按同样规则补标。

### 4.2 看板口径

- 「知识库命中」改为 **有效命中率 = grounded ÷ (grounded + no_info + general)**，分母只含业务问题。按这个口径线上现在约 50%。
- 增加「检索命中率」（检索调用有结果的比例）和「引用但没资料」数，三个数并排，一眼看出问题在覆盖还是在检索。
- 新增 **「未命中问题」** 页：来源是检索未命中的 query、no_info 的回答、以及没检索的真实问题；按向量相似度归并同类（阈值 0.85），显示次数和最近时间；每条可一键「新建知识」，标题预填问题，或「忽略」。这是补知识的工作台，取代现在只能跑命令行的 mine_bad_cases。

### 4.3 引用清洗与回答策略

- 落库前只保留回答正文里实际出现的 [来源N] 对应的引用；一个都没引用则清空 citations。客户端看到的引用因此和回答一致。
- search_knowledge 工具的返回文案加一句：「若以上资料没有直接回答用户的问题，请明确告知知识库暂无相关资料，不要标注引用，不要猜测具体入口或操作路径。」解决「我的订单」这类凭空猜入口的问题。
- 工具描述里的改写要求改为：**保留用户原话的自然问句，只补全指代**。现在的「长关键词串」改写（动辄 40 字以上）对向量检索没有好处。

### 4.4 首轮强制检索 + 双查询

- 一轮对话的第一次模型调用强制 `tool_choice = search_knowledge`，例外只有：寒暄/极短消息、要人工、防滥用已拦截。图片输入已经这样做了，推广到全部。这样 26 条「没检索就答」的真实问题会归零。
- 检索时同时用「用户原话」和「模型改写的 query」各查一次，RRF 融合后再重排。成本是多一次 embedding（有查询缓存），收益是改写跑偏时原话兜底。

### 4.5 两个小修

- 重排开启时，候选只有 1 个也走重排，让 `min_score` 门槛和分数口径在所有路径一致（现在单候选直接返回融合分 0.0167，看板的平均分被这些值拉偏）。
- 工具返回的未命中文案里带上「最高相似度」等诊断字段只写日志不给模型，避免模型把诊断信息复述给客户。

## 五、二期：知识库结构重构为 FAQ 型

现状是「文档型」：一条知识 = 标题 + 正文，正文切块后做向量。对你的业务来说知识 90% 是短问答，客户的问法和正文措辞差异大（「显示限额了」对「提示额度限制，换号新开对话」），这正是模糊问题重排分只有 0.17–0.21 的原因。

### 5.1 同义问法（questions）

- 知识条目新增 `questions: list[str]`（存 `extra` 或新列），编辑页一个「客户可能怎么问」的多行输入。
- 入库时每条问法单独生成一个 question-chunk（标记 `kind='q'`，`content` 存问法，`item_id` 指向条目），正文照旧切块。
- 检索时问法块和正文块一起召回，按条目合并，命中问法的条目加权（问对问的相似度通常比问对答高 0.15–0.25），注入给模型的仍是正文。
- 保存条目时调用 LLM 生成 6–8 条候选问法，编辑勾选确认后入库；「未命中问题」页里点「归入某条知识」也直接追加为该条目的问法。这样未命中问题每处理一次，知识库就学会一种新问法。

### 5.2 缺口闭环（把人工回复变成知识草稿）

- 坐席站会话页加「沉淀为知识」按钮：选中一段人工回复，LLM 结合上下文整理成「问题 + 答案」草稿，进入现有待审核队列（knowledge_review_candidates 已具备全部字段，不需要新表）。
- 工单关闭时自动做一次：若该会话里有人工回复且客户问题在知识库未命中，生成候选并标注来源会话。坐席不用额外操作，管理员在待审核里批量过。
- 待审核页加「合并到已有条目」动作（作为问法或补充段落），而不只是新建。

### 5.3 文档站导入

「使用文档」现在只有一个链接。把 docs.9e.lv 的 Markdown 导进知识库（现有批量导入支持 Markdown），按页面切条，分类「使用教程」。这样「Claude Code 怎么配置」「桌面版怎么装」能答出步骤而不是一个网址。需要你确认文档站内容允许全文进知识库，以及给我导出或抓取的方式。

### 5.4 条目质量提示

知识列表页加两列：问法数、近 30 天无引用标记。保存时对不足 30 字且无问法的条目给出提示，引导补问法。

## 六、三期：参数页重构为「不用调」

### 6.1 哪些参数真正重要

| 参数 | 现在值 | 对命中的实际影响 | 建议 |
|---|---|---|---|
| 重排分下限 min_score | 0.15 | 唯一决定「要不要把沾边结果当命中」的开关，但 2.2 证明单靠它切不开 | 保留，由校准决定；三期前不要动 |
| 向量相似度下限 vector_min_sim | 0.5 | 无重排时的主门槛，有重排时是预筛 | 保留，由校准决定 |
| Top-K | 5 | 影响上下文长度，不影响第一名 | 固定 5，折叠 |
| 重排 Top-N | 3 | 代码里取 max(Top-N, Top-K)，实际恒为 5，**这个参数现在无效** | 删除或与 Top-K 合并 |
| 向量/关键词权重 | 0.6/0.4 | 有重排时只影响进重排的顺序，几乎无感 | 折叠 |
| 候选倍数 | 8 | 12 条知识时候选池永远是全部，无感；知识上千时才有意义 | 折叠 |
| Trigram 阈值 | 0.4 | 只影响英文/编码类子串匹配 | 折叠 |
| 分块大小/重叠 | 600/100 | 现在所有条目都不到 600 字，一条一块，完全无感 | 折叠，改动需重建 |
| 上下文扩展 | 开 | 单块条目无感 | 折叠 |
| 关键词回查下限 keyword_min_sim、单条目上限 per_item_max、上下文 token 预算 | 0.35/2/4000 | 后台根本没露出来，只能改配置文件 | 进高级区 |

### 6.2 页面改法

- 基础区只留一个「检索严格度」三档：严格 / 均衡（默认）/ 宽松，对应 (min_score, vector_min_sim) = (0.25, 0.55) / (0.15, 0.50) / (0.10, 0.45)，旁边用一句话说明「严格：宁可说没有也不乱答；宽松：尽量给资料」。
- 「高级参数」折叠面板，默认收起，每个参数的说明改为「什么情况下才需要动」，并修正现在错误的提示（向量下限提示写的 BGE 0.4–0.5，实际 text-embedding-v4 校准值是 0.5–0.6；重排 Top-N 的说明与代码不符）。
- 显示「当前生效值 / 默认值 / 一键恢复默认」。

### 6.3 评测集从后台来，一键校准

- 「测试检索」弹窗加两个按钮：「应命中这条」「应该无结果」，保存为评测用例（新表 `retrieval_eval_cases`：query、期望条目或空、来源、创建人）。未命中问题页处理时也可一键存为用例。
- AI 配置页加「一键校准」：对评测集扫描 min_score 0.05–0.40 和 vector_min_sim 0.40–0.65，输出每组的命中率与误报率表，推荐一组并可一键应用；同时给出「当前配置在评测集上的成绩」，以后改任何参数都先看这个数。
- 现有 scripts/rag_eval 的逻辑复用，不再要求命令行。

## 七、不做什么，以及为什么

- **不换 embedding 模型**：text-embedding-v4 在对题时相似度 0.6–0.9，区分度够；换模型要全量重建且没有证据会更好。
- **不换或关闭 rerank**：gte-rerank-v2 对精确问题给 0.86–0.93 很可靠，对模糊问题分低是因为知识条目本身短且措辞不像答案，二期的问法块会直接改善这一点。
- **不调分块、权重、候选倍数**：当前知识规模下全部无感。
- **不现在动 min_score**：往上丢对题，往下多误报，三期有评测集再定。
- **不加语义缓存**：问题量级（每天约 10 条）用不上，缓存错答案的风险大于收益。

## 八、你现在就能做的（不需要等代码）

1. 按第 2.4 节 8 个主题补知识，每条写成「标题是客户的问法，正文是直接答复」，例如标题「GPT-6.1 为什么用不了」而不是「模型说明」。
2. 把「web镜像」「API中转站」两条从一个网址扩成完整段落：是什么、怎么进、支持哪些模型、常见问题各一句。
3. 「使用文档」条目至少把最常问的 3 个操作（Claude Code 配置、桌面版安装、分组选择）的步骤贴进来。
4. 后台「测试检索」里用 2.4 的问法试一遍，命中不对的记下来，二期做问法时直接用。
